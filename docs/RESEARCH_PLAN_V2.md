## 1. Evidence taxonomy — mandatory labelling

Per your instruction, **every variable, every experiment and every conclusion carries one of these tags.** This is enforced in code (§5.4), not left to discipline.

| Tag | Meaning | Examples in this project |
|---|---|---|
| **M — Measured** | Directly logged by a physical sensor | HV battery current, vehicle speed, **onboard outside-air temperature**, **A/C & heater power**, SOC |
| **D — Derived** | Computed from measured data by a documented transform | `wh_per_km`, `stops_per_km`, `speed_std`, aggressiveness index, `headwind_ms` (from external wind × bearing) |
| **X — External** | From a third-party dataset or model, not measured by the vehicle | eVED map-matched elevation & speed limits (OSM), Open-Meteo wind & precipitation (ECMWF reanalysis) |
| **S — Simulated** | Generated by our own code | Everything from `src/data/synthetic.py` |
| **A — Assumption** | A constant or modelling choice we impose | `regen_eff = 0.40`, vehicle mass (static file is *generalised*), temperature-derate form, timezone offset (until Gate G1 resolves it) |

### 1.1 Conclusion strength — three levels, never blurred

| Level | Permitted wording | When |
|---|---|---|
| **DEMONSTRATED** | "we measured", "we observed", "on held-out segments, X" | A result produced on **M/D/X** data under a declared split |
| **SIMULATED** | "in simulation", "under our propagation model, X" | Any result involving **S** or **COUPLED-SIM** |
| **ASSUMED** | "we assume", "taken from datasheet/literature" | Any **A** input |

### 1.2 Causality discipline

VED is **observational**. Nothing in it was randomised. Therefore:

- ✅ **Permitted:** *"segments in colder conditions showed higher consumption (association)"*, *"removing weather features increased CV error by X"* (a statement about the **model**, not the world).
- ❌ **Forbidden:** *"cold weather causes X % range loss"*, *"aggressive driving reduces range by Y"*.
- ⚠️ **The counterfactual subtlety that must be stated:** `advisor.explain()` answers *"what would the **model** predict if this input were different?"* — **not** *"what would happen in the world?"* It is a **model-internal counterfactual**, valid for explaining a prediction, invalid as a causal claim. Confounders are real here: temperature is correlated with HVAC use, season, tyre pressure and traffic, and we can separate none of them observationally.
- **Where the physics layer *does* carry causal content**, it is by *assumption* (Newtonian road load), not by inference from this data — and that is stated as **A**, not **DEMONSTRATED**.

### 1.3 Required per-experiment evidence table

Every experiment writes this block into `reports/<exp_id>/EVIDENCE.md`. No result is reported without it.

```
Experiment:       E<k> — <name>
Measured (M):     <sensor signals used>
Derived (D):      <computed features + the transform>
External (X):     <third-party sources + resolution/uncertainty>
Simulated (S):    <none | what, and why simulation was necessary>
Assumptions (A):  <every constant and modelling choice>
Split protocol:   <grouping key, level L0–L4>
n:                <segments, vehicles, groups>
Conclusion type:  DEMONSTRATED | SIMULATED | ASSUMED
Claim strength:   association-only | model-internal | physical-by-assumption
Known confounds:  <unobserved payload, HVAC/temp correlation, ...>
```

## 2. Finalized Research Questions

Three questions. Each has an outcome **genuinely unknown before the experiment runs** — the test of a real research question. All three are answerable with **open data** and the **Nissan Leaf** as primary vehicle.

---

> ### **RQ1 — Does the physics prior buy robustness, or only accuracy?**
>
> *When an EV consumption model is evaluated under progressively harder distribution shift — unseen routes, unseen temperature regime, unseen vehicle, unseen vehicle model — does the physics-informed hybrid degrade more slowly than a pure-ML model of equivalent capacity?*
>
> **Why non-trivial:** published hybrid papers report in-distribution accuracy. The prior's actual selling point — that road-load physics **extrapolates** where gradient-boosted trees structurally cannot — is asserted far more often than measured.
> **Headline metric:** **degradation ratio** `D = MAPE(L_k) / MAPE(L1)`. A model can win on accuracy and lose on D.
> **Data:** VED BEV + PHEV-electric segments + eVED + Open-Meteo. All **M/D/X**. `DEMONSTRATED`.
> **Both outcomes are useful:** if the hybrid holds, the prior is justified; if not, that is a genuine negative result about physics-informed ML on real data.

> ### **RQ2 — Is the range band trustworthy *where it matters*?**
>
> *Do split-conformal intervals achieving correct marginal coverage retain coverage **conditionally** — within cold-temperature, high-grade and high-congestion subgroups — and do CQR or Mondrian (group-conditional) conformal repair it, at what cost in interval width?*
>
> **Why it matters physically:** a rider is stranded by a band that fails on a cold evening, not by one that fails on average. **Marginal coverage is the wrong guarantee for range anxiety.**
> **Metrics:** marginal coverage, **worst-subgroup coverage**, mean relative width, coverage-vs-width trade-off.
> **Bonus:** diagnoses the existing real defect — quantile intervals cover **0.73 against a 0.90 target** (`reports/uncertainty.csv`).
> **Data:** same as RQ1. `DEMONSTRATED`.

> ### **RQ3 — How much of the range error is the battery's fault?**
>
> *When SoH is **estimated** (carrying its measured leave-one-battery-out error distribution) rather than assumed, how does the range interval widen — and what fraction of total range-error variance is attributable to consumption-model error vs. SoH-estimation error vs. temperature-derating uncertainty, as a function of segment length and starting SoC?*
>
> **Why it closes the project:** it converts "SoH-coupled" in the title from an assertion into a measurement, and yields a directly useful engineering number: **km of range error per percentage point of SoH error.**
> **⚠️ Labelling — mandatory and non-negotiable:** **`COUPLED-SIM`. This is a propagation study, NOT real-world end-to-end validation.** No public dataset contains both a vehicle's trips and its pack SoH trajectory. This limitation appears in the abstract, on the figure, and in the UI panel — not buried in a limitations paragraph.
> **Data:** consumption side **M/D/X** (real); SoH error distribution **M/D** (real NASA cells); coupling **S** (Monte-Carlo propagation). Conclusion type: `SIMULATED`.

**Deferred to future work (documented, not attempted):** cross-vehicle-class generalization (ZTBus), pack-level SoH from real fleets (EVBattery), Indian road/climate validation.

## 4. Revised Experimental Design

Every experiment: **5 seeds**, mean ± std, its own `reports/<exp_id>/` with `EVIDENCE.md`, `config.json`, `MANIFEST.json` (seed, data hashes, code revision).

### 4.1 The shift ladder (revised for decisions 1 & 2)

| Level | Split | n (vehicles) | Question |
|---|---|---|---|
| **L0** | Random rows | 3 | *Leaky control* — quantifies what a naive split fabricates |
| **L1** | Unseen **route** (`route_id`) | 3 | Current standard practice |
| **L2** | Unseen **temperature regime** — fit warm, test cold | 3 | Does it survive a winter it never saw? |
| **L3** | Leave-one-**vehicle**-out | **3** | Does it survive a different car of the same model? *(weak: n=3 — state it)* |
| **L4** | **Cross-vehicle-model** — fit on 3 BEV Leafs → test on **PHEV electric-mode segments** (4 models, ≤24 vehicles) | **≤27** | Does the *model form* transfer when only parameters change? |

**L4 replaces the dropped ZTBus experiment** and is verified feasible: PHEV `Engine RPM` has 100 % availability, so electric-mode segments are identified by `RPM == 0` throughout plus a guard band. (`Fuel Rate` cannot be used — 50 % availability for PHEVs, 0 % for EVs.) Vehicle parameters are **re-identified per model**, never shared.

| ID | Name | Tier | Answers | Output |
|---|---|---|---|---|

### 4.3 Metric change
`range_MAPE` is **removed** — it cancels algebraically to `|y−ŷ|/ŷ` and measures nothing about the battery coupling (investigation §3). Replaced by **`range_km_error`**: absolute error in predicted kilometres at a stated SoC and SoH. That is the quantity a rider experiences, and it does not cancel.

### 4.4 Statistical honesty
With n = 3 vehicles at L3, model differences are reported as **paired per-route errors with a Wilcoxon signed-rank test**, never as two bare means. **Sample size is printed next to every claim.**

## 5. Leakage and Circularity Prevention

### 5.1 The circularity fix — structural, not procedural

The current 2.93 % MAPE is circular because `_true_wh_per_km()` calls the **same** `segment_energy_wh()` that produces the `phys_wh_km` feature (investigation §3).

**Three-layer defence:**

1. **Real data replaces synthetic as the evidence base.** Real `wh_per_km` comes from a current sensor. No function we wrote can generate it. **Circularity is impossible by construction.**
2. **Archive, never rescue.** Existing `reports/*` move to `reports/archive_synthetic/` with a README explaining why they are not evidence. **They are never re-reported, never tuned, never quoted.** Keeping them, labelled, documents the project's own history — a strength, not an embarrassment.
3. **Synthetic data is demoted to two roles only:** (i) fast deterministic CI fixtures, (ii) **identifiability studies** requiring known ground truth (e.g. *"can E7 recover Crr from N noisy segments?"* — unanswerable with real data, since the true Crr is unknown).
   **De-circularisation requirement:** if the synthetic generator is retained for (ii), its truth **must not be produced by the baseline's own function**. An automated test asserts that the generator does not call `segment_energy_wh` with baseline parameters. **No synthetic accuracy number ever appears in the abstract or conclusion.**

### 5.2 Leakage register

| Risk | Mechanism here | Control |
|---|---|---|
| Route leakage | Same route in train and test | `GroupKFold`/`GroupShuffleSplit` on `route_id` + `assert` *(exists)* |
| Vehicle leakage | Same car in train and test | Leave-one-vehicle-out (L3), cross-model (L4) **[NEW]** |
| **Battery-label leakage** | A cycle's own capacity (or a derivative) used as a feature | Feature whitelist + **a unit test that fails if any capacity-derived column enters `SOH_FEATURES`** **[NEW]** — enforces `CLAUDE.md` rule 2 |
| **Temporal leakage** | Training on later periods, testing earlier | Time-ordered splits; L2 is **train-warm → test-cold**, never shuffled **[NEW]** |
| Calibration leakage | Conformal calibration sharing routes with train or test | Three-way route-disjoint split *(exists — re-assert after refactor)* |
| **Preprocessing leakage** | Scalers fitted before splitting | All preprocessing inside per-fold `sklearn` Pipelines **[FIX]** |
| **Segment-adjacency leakage** | Consecutive segments of one journey landing on both sides of a split | Group by **journey**, not just route **[NEW — arises from the L2 segment redefinition]** |
| **Weather leakage** | Using information unavailable at departure | Reanalysis stated as *"as it turned out"*; limitation L7 **[NEW]** |
| Tuning leakage | Hyper-parameters chosen on test | Nested CV on dev only; **test touched once** **[NEW]** |
| Selection bias | Silently dropping hard segments while cleaning | **Attrition log**: every exclusion with reason and count, published **[NEW]** |

### 5.3 Pre-registration
`docs/HYPOTHESES.md` records the RQ1/RQ2/RQ3 hypotheses **with a date, before E2/E4/E6 are run**. All levels and all models are reported, including unflattering ones. This prevents result-shopping — the integrity risk that most threatens a multi-split study.

### 5.4 Mechanical enforcement
`src/evaluation/provenance.py` **refuses to emit a metrics table that mixes provenance tags** (REAL / SYNTHETIC / COUPLED-SIM) unless explicitly forced with a logged override. Rules become code, not good intentions — and this is demonstrable live in the viva.
